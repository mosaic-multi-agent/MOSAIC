# mosaic-run (MOSAIC Script-Driven Orchestration Runner)

> Purpose: A Go CLI/TUI tool that drives a MOSAIC multi-agent orchestration run to completion — reading a workflow definition and an in-progress orchestration artifact, deciding which subagent to dispatch next, invoking it through a harness, and recording the outcome — without requiring an LLM orchestrator agent to manually run the loop.

## Areas / Domains

| Area | Responsibility | Key Relationships |
|------|---------------|-------------------|
| **domain** | Defines all value types, enums, and port interfaces (`HarnessAdapter`, `ArtifactStore`, `RoutingConsultant`, `PreConsultant`, `RawInvoker`, `ApprovalReader`, `OutputWriteDetector`, `Clock`, the log writers, and `Interaction`, which re-exports the shared `mosaic-common/interaction` port) shared by every other package. Also owns the pure policy types: `ExecutionMode`, `WorkflowRow` (the 1-based routing-table row number), iteration-value formatting and row-aware reading (`FormatIterationValue`, `ReadIterationValue`), `DecideHITLCompliance`, dispatch-target validation, and the review loop limit parser. Zero dependency on other internal packages. | Depended on by everything; depends on nothing internal. |
| **orchfile** | Reads an orchestrator agent file and enumerates its embedded `<Workflow type="core" name="{id}">` regions (workflow definitions), each carrying an id, version (from the region's `version` attribute), and raw content. | Feeds raw workflow content to **workflow**. Also enumerates each infrastructure agent's declared triggers and refuses any trigger outside the vocabulary (`INVOCATION_INTERVAL`, `ITERATION_END`, `PHASE_END`, `MANUAL`). |
| **workflow** | Parses a workflow region's raw markdown, under WorkflowFormat 2.16 only, into a flat, ordered, index-identified routing table (`RoutingTable`) with the `**Blocks:**` and `**Groups:**` tables, per-row block references, group and bare agent id, and typed `On Success` / `On Findings` / `Waits For` entries resolved to row indices. Any 1.x notation is refused with the format rule ID (T-, P- rules), the 1-based row and the offending token. | Consumes **orchfile** output; feeds **compat**. |
| [**compat**](./compat/Index.md) | Validates, for the run's execution mode, that a parsed routing table is within the supported workflow subset ("admission") and resolves each declared block into its contiguous row range, its groups (the Phase column's group segment), its approach rows and its schedule-source classification (seeded or produced). | Consumes **workflow** output; feeds **engine** (`AdmittedWorkflow`). |
| **planstages** | Reads a block schedule from the `Source` and `Section` its workflow declares and returns a validated, ordered `BlockSchedule` (iteration IDs of letters, digits and `-`, unique ignoring case; `Depends On` naming earlier IDs; `HITL` exactly `TRUE` or `FALSE`; `Approach` required and declared for a grouped block, ignored for an ungrouped one). A defect is a `*domain.ScheduleDefectError` carrying the V-rule ID, the 1-based data row and the token. | Feeds **engine** and **session**; re-invoked mid-run by **session** when a row produces a block's `Source`. |
| **agentresolve** | Resolves every agent identifier referenced in a workflow to its agent definition file in the directory containing the orchestrator file, by exact filename-stem match. | Feeds **engine** (agent references) and **session**. |
| **artifact** | Implements the `ArtifactStore` port: reads, constructs, and atomically (write-temp-then-rename) rewrites `Orchestration.md` in the canonical format. Tables are written compact (no column padding) with every cell sanitised (line breaks become spaces, pipes escaped) and read back with a structural check (a row with more cells than its header is a refusal naming the section). The Execution Log (OrchestrationArtifactFormat 3.0) carries an `Iteration` column and a `WorkflowRow` column and a trailing `[error:CODE]` marker on BLOCKED summaries; an artifact in the pre-3.0 layout (a `Stage` column or `current_state.stage`) is reported as `artifact.ErrPre30Layout` and refused on resume; input and registry paths are recorded without the `Orchestration-{run_id}/` prefix. New artifacts record `dispatch: sequential` (after `global_sequence`); a present value survives rewrites and a missing one is read as `sequential`. Also provides `SetPhase` (final COMPLETED marker), the `human_approved` reader and the output-write detector used by the HITL gate. | Read/written by **session**; format understood by **engine** indirectly via `ArtifactState`. |
| [**engine**](./engine/Index.md) | The pure, side-effect-free decision core. Given the admitted workflow, block schedules, execution mode and current artifact state, `Next` answers "what happens next": Dispatch, Complete, Deviation, Consult, or Stop. Routes by the typed `On Success` entries within their scopes (run, group, iteration) and derives the current row and iteration from the Execution Log's recorded `WorkflowRow` and `Iteration`, and owns the bounded mechanical retries and the review loop limit. No I/O, no clock reads except via injected `time.Time`. | Consumed exclusively by **session**; imports only **domain**. |
| [**session**](./session/Index.md) | The use-case loop connecting the pure engine to the outside world. Drives the full run lifecycle: run-start sequence (load orchfile → parse workflow → read artifact → admit via compat → resolve agents → snapshot → read block schedules and settle run settings → create or resume artifact → commit setup → overrides and pre-consultation) then the dispatch loop (ask engine → dispatch via harness → HITL gate → apply to artifact → repeat), including routing consultation, block schedule re-reading with the defective-schedule re-dispatch, and graceful stop. | Orchestrates nearly every other package; driven by **cli** and **tui**. |
| [**harness**](./harness/Index.md) | Implements the `HarnessAdapter` port. Includes a `MockAdapter` for tests (scripted responses), `ClaudeCodeAdapter` (spawns the Claude Code CLI using `--permission-mode dontAsk` + `--allowedTools` derived from agent frontmatter), `GHCPCLIAdapter` (supports Blanket `--yolo` mode or Partial Allowlist `--allow-tool` mode selected per run), and `OpenCodeAdapter` (spawns OpenCode with `--auto` which converts `ask` permissions to `allow` without a per-tool allowlist). | Invoked only by **session**, always through the `domain.HarnessAdapter` port (import-boundary enforced). |
| **deviation** | Implements the `RoutingConsultant` and `PreConsultant` ports with two strategies: `OrchestratorConsultant` (sends the two-action `dispatch`/`stop` consultation to the script-mode orchestrator over the `RawInvoker` transport; a dispatch reply names the 1-based `row`, the bare `agent` and, for a block row, the `iteration` (the log's `Iteration` value), and is validated against the routing table and the block schedules; invalid replies are retried up to three attempts) and `ManualResolver` (a step-by-step dialogue over the `Interaction` port: row, iteration, task, input and output artifact multi-selects pre-checked with the row defaults and accepting free-form paths, constraints, HITL override; Esc steps back; bounded by `ManualInvalidResultLimit` and `ManualPromptLimit`). Never originates a HITL override on its own. | Invoked by **session** for every routing consultation (orchestrated-mode decisions and engine deviations). |
| **runscan** | Scans the working directory for `Orchestration-{run_id}/` folders and classifies each as resumable or completed, for run-selection UX. | Used by **tui** (and CLI run-selection) at startup. |
| **cli** | The non-interactive frontend. Resolves all setup questions from flags, writes per-step progress to stdout, and defines the tool's exit codes. Its `Interaction` answers `SelectOne`, `SelectMany` and `AskText` with the `Unsupported` status (never an empty `Answered`) and `Confirm` with `Answered` and `Confirm=false`. | Drives **session**; never imports **tui**. |
| **tui** (+ **tui/screens**) | The interactive frontend, built on Bubble Tea, sharing theme/keys/scaffold from the shared `mosaic-common/tui` library. Collects run setup interactively, starts the session in a background goroutine, shows live progress, answers the session's `Interaction` questions through overlays (select-one, a multi-select overlay built on the common `MultiSelect` with pre-checked defaults and free-form entries, a paste-safe text overlay, confirm), and lets the user inspect the artifact. Every restart (done-screen Continue, stop recovery, executable-override retry) goes through one `restartAsResume` path that resumes a run whose artifact exists and seeds the progress screen with the Execution Log history. | Drives **session**; never imports **cli**. |
| **cmd/mosaic-run** | The single binary entry point. Decides CLI vs. TUI mode (`--tui` flag, explicit subcommand, or TTY detection), pre-scans flags needed for dependency wiring, resolves run identity, and wires all infrastructure (harness, artifact store, routing consultant, manual resolver, clock) before handing off to the chosen frontend. | Constructs and injects concrete implementations of every domain port; the only place that does so. |
| **tools/importcheck** | A standalone static-analysis command that enforces the module's import-boundary rules (see System-Wide Patterns) by scanning non-test source files. Run via `task check:imports` as part of `build-checked`. | Governs, but is not depended on by, the rest of the module. |

## System-Wide Patterns

- **Ports and adapters (hexagonal architecture):** `domain` defines interfaces (`HarnessAdapter`, `ArtifactStore`, `RoutingConsultant`, `PreConsultant`, `Clock`, and the others listed above); concrete implementations live in leaf packages (`harness`, `artifact`, `deviation`) and are wired together only in `cmd/mosaic-run` (the `Interaction` port is supplied by the chosen frontend, `cli` or `tui`). No use-case or adapter package outside `harness` itself may import `internal/harness` directly — all access goes through the `domain.HarnessAdapter` port.
- **Layered import direction, enforced by `tools/importcheck`:** `domain` imports nothing internal → `engine` imports only `domain` → `session` imports the core packages (`domain`, `engine`, `orchfile`, `workflow`, `compat`, `agentresolve`, `planstages`) but never `tui` or `cli` → `tui`/`cli` import `session` and `domain` but never each other. This boundary is a build-time gate (`task check:imports`), not just a convention.
- **Engine purity:** The `engine` package must contain no filesystem, network, randomness, or `time.Now()` imports — all time-varying data arrives as parameters. This is what makes deterministic golden-file testing of full runs possible.
- **Refusal over silent fallback:** Every package that validates input (orchfile, workflow admission via compat, planstages, agentresolve, artifact parsing) reports invalid input as a `*domain.RefusalError` naming the component, the resource, and the specific condition — never a silent default or best-effort guess.
- **Pure decision core / imperative shell:** `engine.Next` is a pure function that decides what happens next; `session` is the imperative shell that performs all I/O (harness invocation, artifact read/write, routing consultation) and drives the loop.
- **Execution mode decides who routes:** every run has a required, immutable `ExecutionMode` persisted in the artifact frontmatter (`runner_mode`). In `orchestrated` the engine never routes (it always returns a Consult decision); in `auto` it routes on SUCCESS and deviates on every other status after its bounded mechanical retries; `auto-review` additionally routes `COMPLETED_NEEDS_ACTION` back to the row's On Findings target until the review loop limit (`review_loop_limit` frontmatter, 0 = none) is reached. An unset mode is a refusal, never a default.
- **Human-in-the-loop gate:** for a dispatch with effective HITL, `session` checks the `human_approved` frontmatter of the output artifacts the attempt actually wrote (found by the output-write detector against a baseline taken before the first attempt). A non-approved output earns one re-dispatch of the same agent; a second failure escalates to a routing consultation. BLOCKED/E503 is exempt. The decision itself is the pure `domain.DecideHITLCompliance`.
- **Workflow position is recorded, not guessed:** each Execution Log row records the 1-based `WorkflowRow`; `engine` resolves the current row from it (validated against the table), falling back to agent-and-phase matching only for rows that record none. A block row's iteration is recorded in the log's `Iteration` column as `{ID}`, or `{ID}.{Group}` for a grouped row (`1.Test`), and `-` outside every block; the pre-3.0 `{Group}.{ID}` and `Stage-N` forms are not read.
- **Communication Protocol v1.12 vocabulary:** Status codes (SUCCESS, COMPLETED_NEEDS_ACTION, PARTIALLY_DONE, NEEDS_CLARIFICATION, CAPABILITY_EXCEEDED, BLOCKED) and error codes (E100, E101, E401, E501, E502, E503) defined in `domain` (which declares the version in its comments) are the shared vocabulary that `engine` routes on and that `harness`/`deviation` parse from subagent responses.
- **Atomic artifact writes:** `Orchestration.md` (the run's persistent state) is always rewritten via write-to-temp-then-rename, never in place, so a crash mid-write cannot corrupt run state.
- **Single owner for text entry and tables:** the Runner's single-line text entry (the TUI text overlay and the common `TextInput` widget) goes through the shared `pastesafe.Field` (a pasted line break never submits and becomes one space), and the artifact's tables are read and written through `mosaic-common/mdtable` with cell sanitising and escaping.
- **Golden-file / fixture-driven testing:** Nearly every package pairs with a `testdata/` fixture directory (`orchfile`, `planstages`, `agentresolve`, `artifact`, `session`, `integration/golden`) containing hand-crafted markdown fixtures exercising valid and invalid shapes; integration tests compare produced `Orchestration.md` output byte-exactly against golden files.
- **External shared library dependency:** Several packages (`orchfile`, `artifact`, `session`, `deviation`, `tui`) depend on a sibling `mosaic-common` module (`mdtable`, `docformat`, `interaction`, `harness`, and `tui` helpers including `tui/pastesafe` and `tui/widgets`) that is outside this KB's scope — treated here as a fixed external dependency, not documented further beyond how the Runner uses it.

## Key Invariants

- No package outside `domain` may be imported by `domain`; no package outside `harness` (and its consumers via the port) may import `internal/harness` directly.
- `engine` remains side-effect-free: no I/O, no direct clock/random reads.
- Every parsing/validation refusal produces a `*domain.RefusalError` — never a panic, never a silently-substituted default.
- `Orchestration.md` writes are always atomic (write-temp-then-rename); direct in-place writes are not used anywhere in the artifact package.
- `cli` and `tui` never import each other; both depend on `session` as their sole entry point into run execution.
- A `DispatchDecision.Steps` slice currently always contains exactly one element — parallel dispatch is not yet implemented but the shape reserves the seam for it.
